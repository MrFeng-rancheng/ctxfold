## A.2 E1 五种上下文策略（5 seeds × 50 轮）

**假设**：用"带守卫的结论状态 + 依赖闭包"替代全量历史，可在显著降本的同时不牺牲证据可得性。

| 方法 | C_cum | R_prompt | 总 token |
|---|---|---|---|
| full（全量） | 0.000 | 0.718 ± 0.045 | 305,768 |
| window-5 | 0.776 ± 0.020 | 0.559 ± 0.039 | 68,486 |
| summary（抽取式） | 0.855 ± 0.010 | 0.542 ± 0.037 | 44,058 |
| grep-RAG（BM25） | 0.858 ± 0.011 | **0.703 ± 0.054** | 43,195 |
| **ctxfold** | **0.920 ± 0.008** | 0.633 ± 0.030 | **24,282** |

**结论**：相对全量省 93%，相对最强基线省 47%，且方差更小（0.030 vs 0.054）。
**代价**：严格可见证据率低 7 个点，5 个 seed 中 4 个如此。

**已知缺陷**：任务合成；summary 基线为抽取式（对它是保守近似）；token 为估算。

## A.3 E2 guard 粒度（改 3 个符号）

**假设**：符号级 guard 的失效集合结构性 ⊆ 文件级，因此误失效更少、重算更便宜。

| guard | 失效条数 | 需重读 token |
|---|---|---|
| file | 20 | 4,007 |
| symbol | 3 | 1,284 |

误失效 **17 条 = 记忆的 70.8%**；重算成本 **3.1×**。

**敏感度**（真实修改 1/3/6 个符号 × 2 seed）：误失效 1–20 条。
**结论**：符号级永远不劣于文件级（结构性保证），但"省多少"取决于改动落在多大文件里——**不能宣传固定倍数**。

## A.4 E3 选择性重算（传播 vs 全量失效）

**假设**：失效沿依赖图传播，只重算受污染子图，比重算全部便宜得多。

| 失效 k | 下游污染（均值） | 传播式重算 token | 相对全量节省 |
|---|---|---|---|
| 1 | 1.34 | 859 | **95.0%** |
| 2 | 2.54 | 1,570 | 90.9% |
| 3 | 3.46 | 2,161 | 87.5% |

（记忆 62 条，used_by 边 43 条，全量失效成本 23,571 token）

**已知缺陷**：污染闭包依赖 1-hop 稀疏图，真实工程更密，成本会上升；
**传播精度（过近似率）离线不可测**，需语义判断。

## A.6 E5 消融（同一任务序列，逐个关掉机制）

| 配置 | 总 token | 相对 base | R_prompt | R_avail | 长程引用 R |
|---|---|---|---|---|---|
| base | 23,670 | 1.00× | 0.626 | 1.000 | 0.429 |
| −closure | 14,818 | 0.63× | 0.561 | 0.705 | 0.326 |
| −placeholder | 34,244 | 1.45× | **0.939** | 1.000 | **0.850** |

## A.7 世界指纹的自身开销

| 语料 | 文件数 | cheap（mtime+size） | content（逐文件 sha256） | 每轮省 |
|---|---|---|---|---|
| `Lib/http` | 5 | 1.1 ms | 2.2 ms | 1.1 ms |
| 整个 `Lib` | 2,213 | **261 ms** | 447 ms | 185 ms |

**结论（负面）**：2000+ 文件时指纹本身超过装配开销两个数量级 ⇒ 必须 `gate_interval` 节流，
代价是**存在最多 N 轮的失效窗口**。这是安全性上的真实让步。

**方法教训**：首版测量未预热，把冷缓存算进去得出 91× 的假差距；预热后才是 2×。

## A.8 抽检：静态 vs 动态

**时延**（世界第 0 轮漂移，问第几轮被发现，5000 次模拟）：

| 机制 | 参数 | 平均检出轮 | 最坏 |
|---|---|---|---|
| 指纹门 | interval=1 | 1.0 | 1 |
| 指纹门 | interval=5 | 5.0 | 5 |
| 静态抽检 | rate=3% | **33.1** | 323 |
| 静态抽检 | rate=25% | 3.9 | 32 |

**结论**：静态抽检检出"世界变了"远慢于指纹门 ⇒ **它不是防错主力**。
**动态抽检**（可执行校验器）才是：2 条结论含 1 条故意写错 → **E = 0.5**，错的标 stale、对的保持 fresh，34ms/条。

**方法教训**：首版模拟把"每轮对 62 条各抽一次"写成"漂移条目每轮 62 次机会"，
得出"抽检更快"的反向结论。**模拟写错比不写更危险，因为它看起来像数据。**

## A.13 tokenizer 校准（估算器 vs cl100k_base）

**问题**：此前文档声称估算器误差约 ±15%。这是**未经验证的猜测**，本轮实测。

| 语料 | 样本 | 中位相对误差 | p10 | p90 |
|---|---|---|---|---|
| `Lib/http` | 221 | **+30.0%** | +5.1% | +48.8% |
| `ctxfold/src` | 62 | 0.0% | −25.4% | +16.9% |

**绝对 token 数**：full 基线估算 271,982 / 真实 210,069（**+29.5%**）；
默认配置估算 22,114 / 真实 19,914（+11.0%）。

**比值类指标**：`C_cum` 估算 0.9187 vs 真实 0.9052，**只差 1.35 个百分点**。

**结论**：
1. 代码文本上，字符估算器**系统性高估**（代码里 `self`、`()`、`_` 等碎片多，平均每 token 字符数显著低于 3.5）；
2. 因此**所有绝对 token 数应视为上界**，不能当作账单预测；
3. 但 C / R / H / E 是比值或计数，同一 tokenizer 对分子分母同比例缩放，
   故**估算误差对结论影响很小（1.35 个百分点）**；
4. 默认仍用估算器（零依赖、跨环境可复现），需要精确值时切 `CTXFOLD_TOKENIZER=exact`。

**方法教训**：文档里写了半年的"±15%"从未被测过，一测是 +30%。
**凡是写在文档里的数字，要么有出处，要么删掉。**

## A.15 在线错误残留率 E（模型自写可执行断言）

**问题**：E 只能在"结论由模型写、且能被外部验证"时才有意义。离线版本（m5）用的是人工构造的结论。

**做法**（`experiments/m8_online_claims.py`）：给模型一段代码，让它写一条 `python -c` 可执行的断言；
我们用 subprocess 真跑一遍，`returncode == 0` 记 pass，否则记 fail。E = fail / scored。

**最终结果**：`experiments/runs/20261112-214232-m8-online-E`，12 个符号

| 指标 | 值 |
|---|---|
| E | **0.417**（5 错 / 7 对） |
| infrastructure 错误 | 0（已从分母剔除） |
| 截断 | 0 |
| 用量 | 3,927 token |

**含义**：模型写的"结论"有约 **四成** 经不起它自己给出的可执行检查。
⇒ 若不经验证就把这些结论固化进状态，**状态会被系统性污染**。
这正是"动态抽检 + 只有可验证的才配被记住"这条判据的实证依据。

**三次测量迭代（全部是我的测量缺陷，不是模型能力）**

| 版本 | E | 原因 |
|---|---|---|
| 初版 | **1.000** | 模块提示写成 `from cookiejar import ...`（缺 `http.` 前缀），全部 ImportError |
| 第二版 | 0.833 | 未设 `max_tokens`，回答被截断（`unterminated string literal`） |
| 第三版 | 0.833 | `clean()` 用 `strip("'")` 把代码末尾引号吃掉 |
| **最终** | **0.417** | 三处修完 |

**方法教训（本项目第三次同类）**：**测量工具的缺陷会把结果推向极端，而且看起来完全像数据。**
E 从 1.0 到 0.42 的每一次下降，都不是模型变好了，是我把尺子修对了。

## A.12 本轮之前已修复的缺陷（全部可复现对照）

| 缺陷 | 影响 | 修复 |
|---|---|---|
| 同名符号遮蔽（`__init__`/`read`） | 13.7% 检索指错对象 | 限定名 `Class.method` + 多候选索引 + 歧义降级为占位符 |
| 类整块与嵌套函数重复计数 | 成本虚高 46%（full 340,790 → 271,982） | 只切叶子（模块级函数 + 类内方法） |
| `BM25.top_k` 预算不足时 `continue` | 偏向短小无关片段 | 改为 `break` |
| 依赖解析按字母序取 top-3 | 对 a/b 开头符号不公平 | 改按源码出现顺序 |
| 依赖解析同名撞车 | `__init__` 抓到别的类 | 同文件 > 同类前缀 > 全局首个 |
| 自动文案写"等成本" | 实际贵 26%，属过度声明 | 改为三句都说 |
| doctor 用平均出度判定 | 损失 54% 的仓库被判成"中等" | 改用模拟损失判定 |
| doctor 的 loss 符号写反 | 打印"损失很小（-54%）" | 修正符号 |
| README demo 数字落后 | 94/45/63 vs 实际 94/76/94 | 按实测回填 |

**共同点：没有一个是崩溃，全部是"结论错误"。** 这类问题只能靠"人眼看输出 + 自检脚本"发现。
