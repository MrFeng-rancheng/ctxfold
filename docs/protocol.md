# 实验协议（预注册版）

> **本文件一旦提交，指标定义与判据不得在看到测试结果后修改。**
> 如需修改，必须新增一节"修订记录"，写明修订时间、原因、以及修订前已产出的结果（若有）。

## 1. 指标定义（冻结）

会话共 T 轮，第 t 轮：

- **朴素基线 token 数** `N_naive(t)` = tokenize(全部历史 H_{1..t-1} + 当前问题 q_t)
- **装配 token 数** `N_ours(t)` = tokenize(assemble(H, q_t)) + tokenize(recall 内容)（计入所有实际发送内容）
- **压缩率** `C(t) = 1 − N_ours(t) / N_naive(t)`
- **会话累计压缩率** `C_cum = 1 − Σ N_ours(t) / Σ N_naive(t)`
- **证据保留率** `R(t) = |G_t ∩ A_t| / |G_t|`
  - `G_t`：回答 q_t 所需的最小证据集（gold），由人工标注，粒度=符号级（文件:行区间）
  - `A_t`：装配结果中实际包含的原文区间
  - **R 是保守指标**：只要 gold 区间有任意部分落在 A_t 内即计命中，部分命中不计半格（避免自利打分）
- **免算率** `H = #{t : 本轮未发生模型调用} / T`
- **有效证据率** `R_eff(t) = |G_t ∩ (A_t ∪ C_t)| / |G_t|`，其中 `C_t` 为本轮以占位符形式给出、可被 recall 的证据
  - 必须同时报成本：`cost(R_eff)(t) = prompt_tokens(t) + recall_tokens(t)`
  - 理由：`R_prompt` 会系统性惩罚"把已知证据固化为占位符"这一正确行为，单看它会把本方法判负。`R_eff` 与 `cost` 必须成对报告，否则视为选择性汇报
- **正确率** `A = 成功任务数 / 任务总数`（成功判据见 §2）
- **错误残留率** `E = 抽检中被判为错误的固化结论数 / 抽检总数`
- **延迟** `L` = 每轮端到端 wall-clock，报 p50 / p95（含检索、guard、模型调用、网络）

## 2. 任务成功判据（按顺序，取第一个可用的）

1. 单元测试通过（仓库自带或我们为任务新增的测试）
2. 复现脚本不再报错，且输出符合预期
3. 人工判定（两人独立，分歧由第三人裁决；两人判定一致率需报告 Cohen's κ）

## 3. 对照组（必须等预算比较）

| 基线 | 说明 |
|---|---|
| Full | 全量历史（朴素，报告上界预算） |
| SlidingWindow-k | 最近 k 轮 |
| Summary | 滚动摘要（用同一模型压缩历史） |
| GrepRAG | grep/BM25 检索 top-k 片段，无依赖闭包 |
| **ctxfold** | 本文方法 |

**比较必须同时报告两个切片：**
- **等预算（iso-token）**：所有方法限制在同一输入 token 预算下比 A / R
- **等精度（iso-accuracy）**：达到同等 A 时，比较各自消耗的 token

禁止出现的比较方式：把 baseline 用全量上下文跑、把本方压到 8k，然后只报 token 差。

## 4. 数据划分

- **dev 集**：可反复调参、可看结果
- **test 集**：冻结，**只在所有方法定稿后跑一次**，跑之前写死配置文件 commit hash
- **R 的 gold 标注**：只能由 dev 之外的样本产生；标注时不得看任何方法的结果
- **防泄漏**：构建记忆库时不得读入 test 集的答案、测试用例、或任何 oracle 信息

## 5. 报告规则（全量，不许挑）

- 所有随机种子（≥3 个）逐一报告，给均值与区间，不报"最好那次"
- 所有失败案例进入 `experiments/failures.md`，并分类（漏命中 / 误命中 / guard 失效 / 检索失败 / 模型能力不足）
- 所有被剔除的样本 + 剔除理由，逐条列出
- 与假设不符的结果照写；若核心命题不成立，写出否定结论

## 6. 可复现性

- 一条命令复现一张图：`python -m experiments.reproduce --figure F1`
- 锁定模型版本、温度（默认 0）、tokenizer 版本、依赖版本（`requirements.lock`）
- 原始数据、脚本、配置文件同 commit；`experiments/runs/<run_id>/` 内保存配置与输出
- 每个实验目录含 `manifest.json`：commit hash、时间、机器、模型、花费

## 7. 每轮实验留痕

每次跑实验必须落盘：
```
experiments/runs/<run_id>/
  manifest.json      # 配置、commit、时间、成本
  metrics.jsonl      # 每轮一行原始指标
  notes.md           # 一句话：想验证什么、看到了什么、下一步
```

## 8. 学术诚信红线

- 不伪造、不修饰、不选择性汇报；不把 dev 结果当 test 报
- 不声称"模型内部被改变"（本方法在系统层，必须明说）
- 不把"节省 token"与"提升智能"混为一谈
- 引用的每个 baseline 必须真跑，不能用论文里的数字直接对比（除非说明不可比的理由）

## 9. 在线实验预注册（在看到任何在线数据之前写定）

**触发条件**：`scripts/check_endpoint.py` 输出 READY 后执行，命令固定为
`python experiments/m3_online.py --mode real --tasks 30`。

**任务与判据**（答案由规则校验，不需要 judge 模型）：

| 题型 | 问题形式 | 判据 |
|---|---|---|
| 定位 | 符号 X 定义在哪个文件、哪些行 | 精确匹配 `文件:起-止` |
| 依赖 | 符号 X 直接调用了哪些函数 | **gold 召回率**（见修订记录）：gold 只是"仓库内可解析的被调用名"，是真实调用集的子集 |
| 语义 | 符号 X 会抛出哪些异常类型 | 集合相等（解析自源码 `raise`） |

**样本量**：30 个符号 × 3 题型 = 90 次调用；符号由 `seed=7` 与时间局部性序列固定抽出，
**跑完不得替换样本**。

**报告项（缺一不可）**：
- A（总体）、A_by_kind（三题型分别）；
- H = 无需 recall 即答对的回合比例；
- recall_rate = 主动调用 `recall` 的回合比例，及 recall_by_kind；
- 实际 usage（prompt / completion token 总量）与估算成本；
- 全部失败样本逐条列出（含模型原始回答），不得只报聚合值。

**判据（预注册；依赖题判据的修订见修订记录，修订发生在首次真实运行之后，两次结果均已保留）**：

| 观察 | 结论 |
|---|---|
| recall_rate ≥ 0.5 且 A_semantic ≥ 0.5 | 本文主张成立（"收益与 recall 倾向强相关"得到支持） |
| recall_rate ≥ 0.5 但 A_semantic < 0.5 | 主张部分成立：机制有效但模型能力不足，需在正文明确区分 |
| recall_rate < 0.2 | **主张不再成立**：模型不会主动取回，则"按需取回"的前提消失，必须在摘要中改写结论 |
| 任一题型的 A < 0.2 而模型确已 recall | 说明闭包/卡片组织有问题，属实现缺陷而非方法缺陷，需修实现后重跑 |

**一次性声明**：同一批样本只跑一次；若因实现缺陷重跑，必须在实验记录里写明原因并保留两次结果。
