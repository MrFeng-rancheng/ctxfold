# 路线图：两条任务线并行

## 总原则

每一轮工作必须同时产出三样东西，缺一不算完成：

1. **可运行的代码变更**（或明确的数据产物）
2. **一条实验记录**（`experiments/runs/<run_id>/`）
3. **一段人话笔记**（`notes/YYYY-MM-DD.md`：想验证什么、看到了什么、下一步）

第 3 条是论文的原始素材。**先有笔记，后有论文**；论文不是最后补写的，是从笔记里长出来的。

## 任务线 A：做出东西

| 里程碑 | 内容 | 完成判据 |
|---|---|---|
| **M0 地基** | 仓库、四份文档、指标脚本（离线 C/R/H） | 拿一个玩具仓库跑出真实数字 |
| **M1 alpha** | 切块 + 符号索引 + guard + 装配 + 账本 + 抽检 + 进展度量 | 50 轮仿真全程跑通，能出 C/R/H 曲线 |
| **M2 beta** | 基线四件套 + 等预算/等精度对比 + 消融 | 出四张主图 |
| **M3 发布** | README/demo/CI/license/一键复现 | 陌生人 clone 后 30 分钟能复现一张图 |

## 任务线 B：论文

| 阶段 | 产出 | 触发条件 |
|---|---|---|
| B0 | 引言 + 问题形式化 + 相关工作的骨架 | M1 跑通后（此时才知道真问题长什么样） |
| B1 | 指标章节（C/R/H/E 定义 + 为什么现有工作只看 A） | 指标脚本稳定 |
| B2 | 方法章节 + 伪代码 + 无损性论证 | M1 定稿 |
| B3 | 实验章节 | M2 完成 |
| B4 | 失败模式章节（含否定结果） | 全流程结束 |

## v0.1 发布的门槛（Definition of Done）

五条同时满足才敢挂 GitHub：

1. `pip install` 后一条命令能在任意本地仓库跑起来
2. README 里每个数字都能被 `make reproduce` 复现
3. 有至少 1 个 baseline 的等预算对比，且列出本方更差的场景
4. 失败模式文档真实存在，包含"它会让你更慢/更贵"的情形
5. 有 `LICENSE`、`CONTRIBUTING`、issue 模板；不吹"通用 AI 加速"

## 风险与止损点

| 风险 | 观测信号 | 止损动作 |
|---|---|---|
| 前提不成立（无冗余可省） | M0 显示 C < 20% | 转向"过程指标 + 分析方法"论文 |
| 误命中率高 | E > 10% 且抽检无法收敛 | 降级策略：默认 T3，只在 T0 放行 |
| 延迟反超 | L 的 p50 高于 Full | 砍检索开销，改符号精确匹配 |
| 状态机打转 | 单轮步数超阈值 | 强制进展度量 + 停机 |
